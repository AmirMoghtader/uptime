# مانیتور آپتایم

سنجش پیوستهٔ در دسترس بودن چند سایت، با یک صفحهٔ استاتیک برای دیدن نتیجه.
همه‌چیز داخل همین ریپو اجرا می‌شود؛ نه سرویس بیرونی لازم است، نه سرور.

متن داشبورد، گزارش هفتگی و خروجی اسکریپت‌ها انگلیسی است و چیدمان صفحه
چپ‌به‌راست. توضیحات کد و همین README فارسی مانده‌اند.

| تکه | کجا | هر چند وقت |
| --- | --- | --- |
| سنجش | `.github/workflows/uptime.yml` → `uptime/lib/check.mjs` | هر ۱۵ دقیقه |
| داده | `uptime/data/YYYY-MM-DD.json` | یک فایل برای هر روز، نگهداری ۹۰ روز |
| نمایش | `uptime/index.html` (ساخته‌شده با `uptime/lib/build.mjs`) | با هر بررسی بازسازی می‌شود |
| آیکون‌ها | `uptime/icons.json` | هفته‌ای یک بار |
| گزارش | `uptime/reports/YYYY-WW.md` (ایجنت هفتگی) | شنبه‌ها |

---

## راه‌اندازی

۱. ریپو را **خصوصی** نگه دارید. دسترسی هر کس را از
Settings → Collaborators می‌دهید.

۲. اجازهٔ نوشتن به Actions بدهید:
Settings → Actions → General → Workflow permissions → **Read and write permissions**

۳. اولین اجرا را دستی بزنید: تب Actions ← **Uptime check** ← Run workflow.
بعد از آن خودکار است.

۴. آیکون‌ها را یک بار بگیرید: Actions ← **Refresh icons** ← Run workflow.

اعداد آپتایم تا چند ساعت بعد که داده جمع شود معنی‌دار نمی‌شوند — درصد
۲۴ ساعته روی داده‌ای که هنوز جمع نشده عدد بی‌ربطی است. زیر هر درصد نوشته شده
بر پایهٔ چند بررسی حساب شده، و نوار ۳۰ روز روزهای بدون داده را خاکستری نشان
می‌دهد نه سبز.

### دیدن داشبورد

GitHub Pages روشن نیست — روی ریپوی خصوصی، Pages فقط با پلن Enterprise واقعاً
خصوصی می‌شود و در پلن‌های دیگر آدرس صفحه برای همه باز است. پس صفحه را محلی
باز کنید:

```bash
git pull && open uptime/index.html
```

`uptime/index.html` یک فایل کاملاً خودکفاست: فونت، آیکون‌ها و همهٔ داده داخل
خودش جاسازی شده‌اند. می‌توانید همان یک فایل را برای هر کسی بفرستید.

> فونت‌ها عمداً base64 داخل فایل هستند و نه `url()` نسبی. مرورگر برای
> `@font-face` قواعد CORS را اعمال می‌کند و روی `file://` فونت کنار خودِ فایل
> را هم بلاک می‌کند و بی‌صدا به فونت پیش‌فرض می‌افتد. با subset لاتین،
> `index.html` حدود ۱۰۰ کیلوبایت می‌ماند.

### چرا هر ۱۵ دقیقه، نه هر ۵ دقیقه

روی ریپوی خصوصی، دقیقه‌های Actions محدود است (پلن Free ماهی ۲۰۰۰ دقیقه).
فاصلهٔ ۱۵ دقیقه ماهی حدود ۱۴۰۰ دقیقه مصرف می‌کند و زیر سقف می‌ماند. اگر
روزی ریپو را عمومی کردید، `cron` در `uptime.yml` و `CHECK_EVERY_MIN` در
`uptime/lib/common.mjs` را با هم به ۵ دقیقه برگردانید.

## اضافه و حذف کردن سایت

**راه اول — دکمه در گیت‌هاب (از گوشی هم کار می‌کند):**

تب Actions ← **Manage sites** ← Run workflow:

| فیلد | برای افزودن | برای حذف |
| --- | --- | --- |
| `action` | `add` | `remove` |
| `url` | `onwebs.ir` | — |
| `name` | `Onwebs` | — |
| `id` | خالی (خودکار ساخته می‌شود) | شناسهٔ سایت، مثل `onwebs` |

خودش `sites.json` را ویرایش می‌کند، یک بررسی می‌زند، آیکون می‌گیرد، صفحه را
می‌سازد و کامیت می‌کند. با حذف، تاریخچهٔ آن سایت هم از فایل‌های روزانه پاک
می‌شود.

**راه دوم — خط فرمان:**

```bash
node uptime/lib/sites.mjs list
node uptime/lib/sites.mjs add "Onwebs" onwebs.ir
node uptime/lib/sites.mjs remove onwebs
```

**راه سوم — ویرایش مستقیم `uptime/sites.json`.** اگر وسط اجرای یک بررسی
ویرایش کنید هم مشکلی پیش نمی‌آید؛ اسکریپت کامیت خودش را با تغییر شما هماهنگ
می‌کند.

> **`id` را عوض نکنید.** کلید تاریخچه است: با تغییر نام یا آدرس سایت نباید
> عوض شود، وگرنه تاریخچهٔ آن سایت گم می‌شود.

## چطور درصد حساب می‌شود

**از زمان واقعی هر بررسی، نه از تعداد بررسی‌ها.**

`cron` گیت‌هاب دقیق نیست؛ در عمل فاصلهٔ اجراها نوسان دارد و گاهی اجرا از دست
می‌رود. اگر فرض کنیم هر رکورد یعنی ۱۵ دقیقه، عدد غلط در می‌آید.

روش درست: هر بررسی نمایندهٔ بازهٔ بین خودش و بررسی بعدی است و درصد وزنی
حساب می‌شود:

```
آپتایم٪ = (مجموع مدت بازه‌هایی که وضعیت بالا بود) ÷ (کل مدت پوشش‌داده‌شده) × ۱۰۰
```

اگر فاصلهٔ دو بررسی از **۴۵ دقیقه** (سه برابر فاصلهٔ اسمی) بیشتر شد، آن بازه
**پوشش‌داده‌نشده** حساب می‌شود و از مخرج بیرون می‌رود — نه بالا، نه پایین. یک
شکاف در داده، قطعی نیست.

«بالا بودن» یعنی کد وضعیت HTTP بین ۲۰۰ تا ۳۹۹. این تعریف و همهٔ فرمول‌ها در
`uptime/lib/common.mjs` هستند و داشبورد و ایجنت هفتگی هر دو از همان‌جا
می‌خوانند، تا هیچ‌وقت دو تعریف متفاوت وجود نداشته باشد.

### محدودیت ذاتی

**قطعی کوتاه‌تر از فاصلهٔ بررسی دیده نمی‌شود.** اگر سایتی سه دقیقه پایین برود
و بین دو بررسی برگردد، در این داده اثری از آن نیست. عدد آپتایم یعنی «در
لحظه‌های بررسی بالا بوده»، نه «یک ثانیه هم قطع نشده».

---

## چرا تاریخچهٔ کامیت شلوغ نمی‌شود

هر ۱۵ دقیقه یک اجرا یعنی ماهی حدود ۲٬۹۰۰ کامیت. به‌جای آن، `commit.sh` نتیجهٔ
هر اجرا را با `--amend` روی کامیت **همان روز** می‌نویسد؛ پس هر روز فقط یک
کامیت با پیام `chore(uptime): daily log` می‌ماند. فایل‌های روزانهٔ قدیمی‌تر از
۹۰ روز خودکار پاک می‌شوند.

## آیکون سایت‌ها

کنار هر آدرس، فاوآیکون خود سایت نشان داده می‌شود. آیکون در Workflow گرفته و
به‌صورت **data URI** داخل `uptime/icons.json` ذخیره می‌شود، نه در مرورگر
بازدیدکننده — وگرنه صفحه هم به شبکهٔ بیننده وابسته می‌شد هم یک درخواست خارجی
اضافه می‌کرد.

ترتیب: اول `<link rel="icon">` صفحهٔ اصلی، بعد `/favicon.ico`. آیکون بزرگ‌تر
از ۳۲ کیلوبایت با ImageMagick به ۳۲×۳۲ کوچک می‌شود. سایتی که آیکون نداشته
باشد، یک دایره با حرف اول نامش می‌گیرد.

## ایجنت هفتگی

شنبه‌ها اجرا می‌شود، دادهٔ هفتهٔ گذشته را می‌خواند و دنبال الگو می‌گردد:

- قطعی‌ها ساعت خاصی تکرار می‌شوند؟ (نشانهٔ کرون‌جاب یا بکاپ)
- زمان پاسخ روند صعودی دارد؟
- یک سایت مدام کندتر از بقیه است؟
- این هفته نسبت به هفتهٔ قبل بهتر شده یا بدتر؟

فهرست قطعی‌ها را دوباره نمی‌نویسد — آن را داشبورد نشان می‌دهد. اگر هفته
بی‌اتفاق بود، همین را در یک جمله می‌نویسد. ایجنت **هیچ سایتی را چک نمی‌کند**؛
فقط دادهٔ از پیش جمع‌شده را می‌خواند.

**اختیاری:** اگر سکرت `ANTHROPIC_API_KEY` را تعریف کنید، متن گزارش با Claude
روان‌تر بازنویسی می‌شود. تحلیل و اعداد در هر حال همان‌هایی هستند که اسکریپت
حساب کرده؛ کار مدل فقط نوشتن است. بدون کلید هم گزارش کامل نوشته می‌شود.

## قیدهای صفحه

- **هیچ درخواست خارجی.** نه CDN، نه فونت گوگل، نه سرویس آیکون. صفحه روی
  شبکهٔ ایران بدون مشکل باز می‌شود.
- **بدون جاوااسکریپت.** همه‌چیز — وضعیت، درصدها، نوار ۳۰ روز، نمودار SVG و
  فهرست قطعی‌ها — موقع ساخت رندر می‌شود. جزئیات هم با `<details>` باز می‌شود.
- **دو کارت در هر ردیف** روی نمایشگر بزرگ؛ زیر ۸۶۰ پیکسل تک‌ستونه می‌شود.
- **فونت‌ها:** **Geist** برای متن و **Geist Mono** برای هر چیزی که عدد است
  (SIL OFL، از Vercel). ارقام هم‌عرض و صفرِ خط‌دارِ مونو باعث می‌شوند ستون‌ها
  با تغییر عدد تکان نخورند و صفحه ظاهر یک ابزار اندازه‌گیری پیدا کند.
  فایل‌های `*.latin.woff2` در `uptime/assets/fonts/` (هرکدام ~۱۱ کیلوبایت)
  همان‌هایی هستند که جاسازی می‌شوند؛ فهرست‌شان در `FONTS` داخل
  `uptime/lib/build.mjs` است.
- **نام سایت فارسی؟** `INCLUDE_PERSIAN` را در `uptime/lib/build.mjs` روی
  `true` بگذارید تا ایران‌سنس هم جاسازی شود (~۳۵ کیلوبایت اضافه).
  ایران‌سنس همیشه در fallback هست، ولی تا جاسازی نشود مرورگر سراغ فونت
  سیستم می‌رود.
- **دو رنگ برند:** `#FFFFFF` و `#133566`. خاکستری‌ها از همان سرمه‌ای با
  شفافیت ساخته می‌شوند. سبز و قرمز فقط جایی که وضعیت را نشان می‌دهند.

## اجرای محلی

```bash
node uptime/lib/check.mjs    # یک بار همهٔ سایت‌ها را می‌زند و ثبت می‌کند
node uptime/lib/build.mjs    # uptime/index.html را می‌سازد
node uptime/lib/icons.mjs    # آیکون‌ها را تازه می‌کند
node uptime/lib/report.mjs   # گزارش هفتگی را می‌نویسد
node uptime/lib/sites.mjs    # فهرست سایت‌ها (add / remove هم دارد)
```

بدون هیچ وابستگی‌ای؛ فقط Node 20 به بالا.
